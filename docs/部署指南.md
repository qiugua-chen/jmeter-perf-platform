# 部署指南

> 从启动到首个压测的完整步骤；排障要点随步骤内联。

## 1. 环境准备
- Docker + docker compose
- Git 仓库（支持 tag 与凭据访问）

## 2. 启动
```bash
cp .env.example .env   # 填写 JENKINS_ADMIN_PASSWORD / GIT 相关
docker compose up -d
```

## 3. 任务自动创建（无需手工操作）
- `init.groovy.d/30-seed-jobs.groovy` 在每次启动时幂等创建/更新两个任务：
  **perf-platform**（三级级联参数 + 构建命令 + 保留 50 次）、**perf-scripts-sync**（RELEASE_TAG 参数）
- 验证：`docker logs perf-jenkins | grep init.groovy.d` 应看到两个"就绪"
- project 下拉清单来自 `config/projects.txt`（单一事实源；首项空白为内置强制选择）：
  改后 `docker compose restart jenkins` 即生效（种子脚本幂等同步）；
  免重启方式：Manage Jenkins → Script Console 粘贴执行 `jenkins/update-projects.groovy`
  （整表幂等，输出 `OK:[, ...]` 即成功；预期首项空 + 你的项目清单）
- 备选路径：种子任务执行 `jenkins/seed-job.dsl`（需 job-dsl 插件）；此路径下
  script/csvFile 级联不会自动生成，需按第 4 节补建

## 4. script/csvFile 级联参数的补建（仅手动路径需要；自动路径已内置）
- Job DSL 无法完整表达 uno-choice CascadeChoiceParameter
- 需用 Groovy 原生 API（removeProperty/addProperty），勿用 updateByXml/POST config.xml：
  XStream 会静默丢弃无法实例化的元素，外部 XML 回写曾触发 500
- 改完必须回拉 config.xml 确认参数块存在 → 查 ScriptApproval pending → 页面验证级联

## 5. scripts-sync 凭据与首次同步
- 凭据传递（模板方式）：.env 的 `GIT_TOKEN` → compose environment → 容器全局环境变量
  → 构建 shell 继承 → scripts-sync.sh 消费。脚本仓库授予只读权限即可
- 打 tag → 手动触发 perf-scripts-sync → 检查 `.sync-version`
- 失败先看控制台 ❌ 行（网络/凭据/tag 不存在三类）
- **无仓库首体验（分钟级）**：脚本必须出现在容器 `/opt/jmeter/scripts/` 级联才有选项。
  尚未建脚本仓库时，先把仓库自带 demo 资产种子进去：
  `docker compose cp scripts/performance perf-jenkins:/opt/jmeter/scripts/ && docker compose cp scripts/common perf-jenkins:/opt/jmeter/scripts/`
  （demo 资产已在仓库 scripts/ 下；此拷贝与后续 GitOps 同步不冲突，正式启用同步后由镜像机制接管）

## 6. 首个压测
- 内置 demo 资产可直接验证 happy path：demo-shop（CSV 参数化，目标 jsonplaceholder 公网演示 API）
  与 demo-order（无 CSV 路径）——参数示例 threads=5 / duration=30 / ramp_up=5
- 完整验收逐项勾选 `docs/验证清单.md`（含级联行为 4 场景、同步幂等、防跑飞兜底）
