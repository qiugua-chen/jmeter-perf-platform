# 下载者验收清单

> 部署后按序勾选。全部通过 = 开箱即用达成；任何一项失败先对照"排障锚点"列定位。
> 注：A 节的脚本/镜像静态检查已由仓库 CI（`.github/workflows/ci.yml`）自动执行——push 到 GitHub 后看 Actions 页绿勾即可，本地可跳过重复项。

## A. 启动前静态检查（无需容器）

- [ ] `cp .env.example .env` 已填写强密码（`JENKINS_ADMIN_PASSWORD` 非空且非弱密码）
- [ ] `docker compose config -q` 无输出无报错（env 插值完整；缺变量会在此处暴露）
- [ ] 已确认 8080 端口未被占用

**排障锚点**：compose 报 `请在 .env 设置强密码` → 密码变量未填。

## B. 首启自动初始化（init.groovy.d 四件套 10→20→25→30）

- [ ] `docker logs perf-jenkins | grep init.groovy.d` 可见插件安装日志，无 `❌` 行
- [ ] 同一日志尾部可见 `perf-platform 就绪` 与 `perf-scripts-sync 就绪`
- [ ] `http://localhost:8080` 可用 .env 中的账号登录；匿名访问被重定向到登录页
- [ ] 任务列表存在 **perf-platform** 与 **perf-scripts-sync**
- [ ] demo 资产已自动种子：`docker exec perf-jenkins find /opt/jmeter/scripts -name '*.jmx'` 可见 demo-shop/demo-order 两个 JMX

**排障锚点**：插件 `❌ 安装失败` 多为离线环境（更新中心元数据拉取失败），见部署指南第 4 节手动安装路径；`uno-choice 未就绪` 说明 10 号脚本失败而 30 号等待超时，重启容器即自动补建（30 号每次启动幂等执行）；demo 未种子先确认 `./scripts` 挂载就位（`docker exec perf-jenkins ls /opt/perf-platform/`）。

## C. 级联参数行为（铁律：改参数结构必须回拉验证）

- [ ] 不选 project → script、csvFile 下拉仅有空白
- [ ] 选 `demo-shop` → script 列出 `demo-shop.jmx`；选中 script 后 csvFile 列出 `users.csv`
- [ ] 选 `demo-order` → script 列出 `demo-order.jmx`；csvFile 仅有空白（演示无 CSV 路径）
- [ ] 直接构建（参数全空）→ 控制台快速失败：`❌ 错误: 未选择项目`，构建标记 FAILURE

**排障锚点**：级联不刷新多为浏览器缓存，强刷（Ctrl+F5）；下拉显示异常值说明 `removeProperty/addProperty` 未生效，重跑 `30-seed-jobs.groovy`。

## D. 发布式同步（perf-scripts-sync）

> 首次无脚本仓库：先用 `docker compose cp scripts/performance perf-jenkins:/opt/jmeter/scripts/`（common 同）把 demo 资产种子进卷，级联立即可选；以下勾选项针对正式接入仓库后。

- [ ] 仓库尚未打 `round/*` tag 时触发 sync → 控制台明确 `❌ 仓库不存在 round/* tag`
- [ ] `git tag round/YYYYMMDD-demo && git push origin round/YYYYMMDD-demo` 后触发 sync → 结尾 `✅ 同步完成: round/YYYYMMDD-demo`
- [ ] 同步后 `.sync-version` 内容与新 tag 一致；`performance|common|monitors` 三个目录已到 `/opt/jmeter/scripts/`
- [ ] 重复触发 sync → 幂等（无差集清理输出、版本不变）

**排障锚点**：`git fetch 失败（网络/凭据）` 检查 GIT_TOKEN / GIT_URL；同步成功但缺目录说明仓库缺对应子目录（本模板已带 monitors 样例，删除须同步改 scripts-sync.sh 的循环列表）。

## E. 首个压测（happy path，需访问公网演示 API）

- [ ] perf-platform 构建：`project=demo-shop`、`script=demo-shop.jmx`、`csvFile=users.csv`、`threads=5`、`duration=30`、`ramp_up=5` → 构建成功
- [ ] 工作区可见 `result-kpi.html`、`errors.html`（本次应为"无错误样本"），浏览器打开中文不乱码
- [ ] 控制台门禁行：`错误率 0.00%` → `✅ 门禁通过`
- [ ] （有网环境）再跑 `demo-order + demo-order.jmx + csvFile 留空` → 验证无 CSV 路径

**排障锚点**：JMeter 报 `BindException`/`TIME_WAIT` 堆积 → 确认 `-Jhttpclient.reset_state_on_thread_group_iteration=false` 已生效（build-command.sh 第 3 段）；CSV 读取失败 → 确认构建参数传了 `csvPath`（`csvFile=null` 时本就不传，属预期）。

## F. 防跑飞与兜底

- [ ] 构建历史仅保留最近 50 次（任务配置 → 丢弃旧的构建 → Max # of builds to keep = 50）
- [ ] （可选实验）构造长时间压测（duration=600）人为断网后，JMeter 进程在 `duration+300` 秒被 timeout 强杀，构建 FAILED 而非挂死

## G. project 清单维护（新增/调整项目）

- [ ] `config/projects.txt` 新增一行项目名后 `docker compose restart jenkins`，下拉出现新项（首项仍为空）
- [ ] 免重启路径：Script Console 执行 `jenkins/update-projects.groovy` → 输出 `OK:[, ...]`，下拉即时更新
- [ ] 新项目选中后 script 级联为空 → 属预期拦截（`scripts/performance/<项目>/` 尚无 JMX），非故障

**排障锚点**：重启后下拉无变化 → 确认 config 挂载就位（`docker exec perf-jenkins ls /opt/perf-platform/config/`）；脚本执行报构造器异常 → 勿自行简化，脚本已内置 XSTREAM2 回退与变更前自校（Jenkins ≥2.568 移除 List 构造器，见部署指南第 3 节）。

> 全过即可进入实装阶段：把 projects.txt 换成你的项目清单 → 接入你的脚本仓库 → 替换 demo 被测地址。
